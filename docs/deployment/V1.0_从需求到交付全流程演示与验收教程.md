# V1.0 从需求到交付全流程演示与验收教程

## 1. 适用范围与验收原则

本教程覆盖 PC 管理端和客户短链确认的 V1.0 主闭环：**需求建档 → 评审 → 技术包发布 → 样品 → 独立质量检验 → 客户确认 → 投产 → 交付 → 完成 → 归档**。

请用新建的干净项目完成演示，不要把预置的 `NSO-DEMO-202607-003` 当作已完成的闭环。该项目被保留为“已确认样品 + 严重风险/受阻任务”的交付阻断示例，用于演示风险处置和非法交付拦截。

不在本次范围内：Compose 部署、备份恢复、性能压测。

## 2. 演示前准备

1. 启动 MySQL、Redis 和后端，PC 管理端访问 `http://127.0.0.1:5173`。
2. 账号必须均为启用状态，并在新项目中配置以下项目职责：

| 操作者 | 系统权限/项目职责 | 用途 |
| --- | --- | --- |
| 项目经理 | `project:*`、项目经理 | 建档、评审、成员、样品、投产、交付、归档 |
| 技术人员 | `document:*`、技术 | 创建并发布图纸，发布技术包 |
| 生产人员 | `task:execute`、生产 | 完成样品备料、样品制作和正式生产任务 |
| 质量人员 | `sample:inspect`、`task:execute`、质量 | 独立完成样品检验任务和合格检验记录 |
| 客户联系人 | 已启用、已获得项目授权 | 使用客户短链提交确认结论 |

3. 在“客户项目”中创建或选择启用客户；项目中至少维护一条需求。项目成员中必须有技术、生产、质量和项目经理，否则创建样品会被阻断。
4. 演示全程保留“项目事件”和“状态历史”页签；每个关键动作完成后截取一张状态和时间轴截图。

## 3. 主闭环演示步骤

| 步骤 | 操作者与入口 | 输入/操作 | 预期状态与证据 |
| --- | --- | --- | --- |
| 1 | 项目经理：客户项目 → 新建项目 | 客户、产品名称、数量、目标交期、至少一条需求 | 项目为 `DRAFT` / `REQUIREMENT`；时间轴出现 `PROJECT_CREATED` |
| 2 | 项目经理：项目详情 → 提交评审 | 提交需求评审 | `REVIEWING`；状态历史出现 `SUBMIT_REVIEW` |
| 3 | 项目经理：项目动作 → 评审通过 | 填写评审原因 | `TECH_PREPARING` / `TECHNICAL`；状态历史出现 `APPROVE_REVIEW` |
| 4 | 技术人员：技术文件 | 上传图纸、发布当前版本；维护 BOM、工艺路线、检验规范并绑定该版本 | 图纸为 `PUBLISHED` 且当前版本唯一 |
| 5 | 技术/项目经理：技术文件或项目页 → 发布技术包 | 发布技术包 | `TECH_PUBLISHED`；状态历史出现 `TECHNICAL_PACKAGE_PUBLISHED` |
| 6 | 项目经理：样品管理 → 创建样品 | 选择项目、用途、数量、计划完成日期、引用当前版本 | 项目自动进入 `SAMPLING` / `SAMPLE`，产生样品备料、样品制作、样品检验、客户确认四类任务 |
| 7 | 生产人员：任务风险 | 依次开工并完成“样品备料”“样品制作” | 两任务均为 `DONE`，各自有任务日志和时间轴事件 |
| 8 | 质量人员：任务风险、样品管理 | 完成样品检验任务；在样品详情新增一条 `PASS` 检验记录 | 样品为 `CHECKED`，留有质量人员和检验时间；创建人不能代替质量人员检验 |
| 9 | 项目经理：样品管理 → 提交确认 | 提交已检验样品 | 样品为 `WAIT_CUSTOMER_CONFIRM`，项目为 `CUSTOMER_CONFIRMING`；未做完备料/制作或未检验会被阻断 |
| 10 | 项目经理：样品管理 → 生成令牌 | 选择已获项目授权的客户联系人，复制 `/public/confirm/{token}` 链接 | 令牌与外部客户身份、项目授权关联；时间轴出现 `CUSTOMER_CONFIRM_TOKEN_CREATED` |
| 11 | 客户：短链确认页 | 选择“通过”，填写确认意见并提交 | 样品为 `CONFIRMED`，项目为 `CUSTOMER_CONFIRMED`；时间轴出现 `SAMPLE_CONFIRMED` |
| 12 | 可选：内部代录 | 在样品行点击“内部代录”，选择结论、填写意见、上传邮件/签字单/截图凭证后提交 | 系统只允许具有 `sample:proxy-confirm` 的人员代录；无凭证返回 `SAMPLE_PROXY_EVIDENCE`；附件关联为 `SAMPLE_CONFIRM` |
| 13 | 项目经理：项目动作 → 准备投产、开始投产 | 分别填写原因 | 依次进入 `PRODUCTION_PREPARING`、`EXECUTING`；手工“进入打样”“转交付”已被禁止 |
| 14 | 生产/质量人员：任务风险 | 创建并完成所有未取消的正式任务；关闭严重风险 | 每个未取消任务均为 `DONE`/`COMPLETED`，不存在 `OPEN + SERIOUS` 风险 |
| 15 | 项目经理/生产：任务风险 → 交付预检 | 选择项目，打开“交付预检” | 后端返回 `ready` 和结构化 `blockers`；预检仅辅助，提交时会再次校验 |
| 16 | 项目经理/生产：交付预检弹窗 | 如实填写交付数量、物流单号、收货人和可选反馈，创建交付记录 | 产生 `SHIPPED` 交付记录，项目自动进入 `PENDING_DELIVERY`；默认假数据不会再被生成 |
| 17 | 项目经理：项目动作 → 完成项目 | 填写完成原因 | 只有存在有效交付记录、任务全完成且无严重风险时可进入 `COMPLETED` |
| 18 | 项目经理：项目动作 → 归档项目 | 填写原因，完成页面二次确认 | `ARCHIVED`；保留项目归档记录、状态历史和审计日志 |

## 4. 交付预检阻断处理

`GET /api/v1/admin/projects/{id}/delivery-readiness` 返回如下结构：

```json
{
  "projectId": 123,
  "ready": false,
  "blockers": [
    { "code": "DELIVERY_TASKS_PENDING", "message": "仍有 2 个未取消任务尚未完成" }
  ]
}
```

| 阻断码 | 处理方式 |
| --- | --- |
| `DELIVERY_PROJECT_STATUS` | 先完成“准备投产、开始投产”，使项目进入 `EXECUTING` |
| `DELIVERY_TECHNICAL_PACKAGE` | 发布并绑定当前技术包，确认图纸、BOM、工艺、检验规范一致 |
| `DELIVERY_SAMPLE_CONFIRM` | 完成客户短链确认，样品必须为 `CONFIRMED` |
| `DELIVERY_QUALITY_CHECK` | 由独立质量人员新增合格检验记录 |
| `DELIVERY_TASKS_PENDING` | 完成或按规范取消剩余任务 |
| `DELIVERY_SERIOUS_RISK` | 在风险中心关闭严重风险；不能用交付动作绕过 |
| `DELIVERY_FIELDS` / `DELIVERY_QUANTITY` | 补齐真实物流单、收货人和正确交付数量 |

## 5. AC-01 ～ AC-08 验收清单

| 编号 | 验收点 | 可复核证据 |
| --- | --- | --- |
| AC-01 | 旧版本任务不能执行 | `VERSION_MISMATCH` 规则码、任务仍为 `TODO`、审计失败记录 |
| AC-02 | 样品未客户确认不得投产 | `SAMPLE_NOT_CONFIRMED`；样品任务与质量检验是前置条件 |
| AC-03 | 变更影响分析覆盖关键对象并阻断受影响任务 | 六类影响记录、审批后受影响任务为 `BLOCKED` |
| AC-04 | 全部影响反馈后才可关闭变更 | 影响项 `DONE`、延误/返工汇总、`CHANGE_CLOSED` |
| AC-05 | 现场异常生成可解释风险 | 风险原因、规则明细、处置建议和时间轴事件 |
| AC-06 | 总览可钻取到项目业务明细 | 概览指标、项目详情、样品/技术版本/时间轴一致 |
| AC-07 | 非项目成员不能读取项目 | HTTP 403 与 `PROJECT_DATA_SCOPE` 审计证据 |
| AC-08 | 幂等重放与乐观锁冲突均被拒绝 | `IDEMPOTENT_REPLAY`、`OPTIMISTIC_LOCK` 及任务状态未被错误覆盖 |

补充回归项：

- 手工 `START_SAMPLING`、`WAIT_CUSTOMER_CONFIRM`、`PENDING_DELIVERY` 返回 `PROJECT_ACTION_SOURCE`；
- 仅在项目与最新样品不一致时显示“同步样品状态”，同步会写状态历史和时间轴；
- 待办里程碑固定显示 `-`，只有已完成里程碑才显示对应完成时间；
- 缺交付记录、未完成任务或严重风险时均不能完成项目。

## 7. 验收边界

本教程证明的是 PC 管理端和客户短链的业务闭环。后端自动化测试、前端构建、接口调用和浏览器流程验证不能替代备份恢复、Compose 部署和性能压测；这些内容需按独立计划验收。
