# V1.0 V16 到 V20 升级与验收手册

## 升级边界

本次升级只追加 Flyway `V17`、`V18`、`V19`、`V20`，不会改写 V1–V16，也不会重编历史项目、客户、样品、变更或任务编号。升级前须完成 MySQL 逻辑备份和附件对象存储清单备份；Flyway 成功后不支持通过删除记录回退，应从升级前备份恢复。

## 执行步骤

1. 停止应用写入，备份数据库与 MinIO 对象索引。
2. 以既有 `application-*.yml` 启动新版 `nso-admin`，由 Flyway 自动执行 V17–V20。
3. 查询 `flyway_schema_history`，确认最高成功版本为 `20`；确认 `nso_business_sequence`、`nso_project_status_history`、`nso_operation_confirmation`、`nso_risk_detail`、`nso_message_recipient_rule`、`nso_import_batch_result` 已建立。
4. 先用只读账号核对项目、样品、变更、任务数量，再开放写入。

## 环境配置与凭据原则

保留现有数据库、Redis、MinIO、JWT 配置。短信、邮件渠道不得把真实凭据写入仓库；未配置外部渠道时，仅站内消息可发送，外部渠道出站记录保留为 `RETRY` 并写明未配置原因，不能显示为已发送。高风险动作的确认挑战、有效期和审计记录均以数据库为准。

## 验收用例

| 场景 | 预期结果 |
| --- | --- |
| 项目状态动作 | 仅允许合法前序状态；请求携带过期 `version` 返回 `OPTIMISTIC_LOCK`；每次成功写入状态历史。 |
| 归档恢复 | 完成项目通过二次确认后归档为只读；恢复也要求二次确认并保留恢复原因。 |
| 编号与幂等 | 并发创建得到不重复业务号；同一请求键不能重复创建。 |
| 字段与数据范围 | 非授权角色读取联系人字段得到掩码，编辑被拒绝；非成员且不在部门范围内读取项目返回 403。 |
| 风险 | 8 类因子、单项上限、0–100 截断、逾期严重；覆盖到期后 Quartz 恢复原始等级。 |
| 消息 | 技术发布、样品临期、任务临期、变更批准、高风险按项目成员矩阵去重；未配置外部渠道不可伪造成功。 |
| 导入与文件 | 导入保留批次成功/失败清单；受控文件下载受项目权限限制。 |
