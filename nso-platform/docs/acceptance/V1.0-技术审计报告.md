# NSO 平台 V1.0 技术审计报告

审计日期：2026-09-12  
审计范围：后端模块、前端 `nso-web`、canonical Flyway、pilot Compose/脚本、验收矩阵及当前工作区变更

## 审计结论

未确认新的高危安全缺陷或阻断级功能缺陷。认证、刷新令牌重放防护、Redis 限流失败关闭、租户条件、项目成员范围、文件 MIME/大小/内容签名、幂等和 Trace ID 均有明确实现；完整测试套件 62 项通过。由于生产配置和运行证据缺失，技术审计结论为“代码质量可接受，生产运行未完成证明”。

Bugbot/独立 Security Review 子代理在当前环境不可调用，本报告采用本地等价静态审查，并明确不把它冒充为已执行的子代理结果。

## 分域审查

### 功能与状态迁移

`pilot-state-transition-matrix.md` 将项目生命周期、需求、技术版本、样品确认、变更影响、任务、文件、报告和租户隔离映射到集成测试；本轮 Maven 全量测试通过。现场业务闭环、录像和审计事件尚未提供，因此只能确认自动化覆盖，不能确认试点操作验收。

### 认证、权限与租户

- `SecurityConfig` 对管理 API 默认要求认证，方法级 `@PreAuthorize` 覆盖项目、样品、变更、任务、文件、报表和系统管理入口。
- `NsoTokenService` 校验 issuer、租户、用户状态、授权版本，并在 Redis 中登记访问令牌；刷新令牌消费后立即删除，具备一次性重放防护。
- `RequestRateLimitService` 在 Redis 异常时返回拒绝，登录保护按 `clientId + username` 计数。
- `ProjectDataScope` 和业务 SQL 使用租户条件，并对项目成员、职责和部门范围做二次校验。

未验证：真实网关转发后的 401/403、跨租户手工回归、刷新令牌并发重放和生产 Redis 故障演练。

### 文件安全

`FileServiceImpl` 限制扩展名、MIME、200MB 大小，使用 `FileContentSignature` 校验 PDF、图片、Office、压缩包、CAD/STEP 头部，并在下载时用 SHA-256 流校验；上传失败会删除已写入的孤儿对象。头像单独限制 2MB。已有测试覆盖错误 MIME、超大文件和 malformed drawing。

### 数据与迁移

canonical 迁移 V1-V39 连续通过，Testcontainers MySQL/Redis 集成测试通过。日志仍出现：MySQL `VALUES()` 弃用告警、V13 重复角色菜单写入告警、V22 重复索引告警。这些目前未导致失败，但会增加未来升级和重复部署的不确定性，应在下一发布前清理或给出明确幂等说明。

### 架构与性能

模块边界清晰，报表服务集中编排项目、样品、变更、任务、风险、消息和审批数据；项目工作台统一调用 `ProjectProgressSemantics`。潜在性能压力来自工作台/报表的多服务聚合和列表后置计算，当前没有真实数据量、P95、慢 SQL 或执行计划证据，不能确认 NFR。

### 前端与部署

前端类型检查和生产构建通过，仅有 Rollup 对 `@vueuse/core` 注释位置的非阻断 warning。Pilot Compose 隐藏 API/数据库端口，仅由 Nginx 暴露 HTTPS；预检脚本会拒绝占位密钥并检查证书。当前缺少真实 `.env.pilot`、TLS、启动状态和网关响应，因此部署审计未闭环。
