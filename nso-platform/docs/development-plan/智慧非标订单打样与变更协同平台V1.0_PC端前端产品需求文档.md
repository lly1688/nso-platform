# 智慧非标订单打样与变更协同平台 V1.0

## PC 端前端产品需求文档

| 项目 | 内容 |
| --- | --- |
| 产品版本 | V1.0 |
| 文档版本 | V0.1 |
| 适用端 | PC 管理端（`nso-web`）及客户公共确认页 |
| 依据 | 《智慧非标订单打样与变更协同平台 V1.0 需求规格说明书 V1.5》 |
| 文档目的 | 为产品、UI/UX、前端开发和测试提供统一的信息架构、页面范围、交互状态和 PC 适配依据。 |

> 本文档仅定义前端产品与交互需求，不包含接口、数据库或代码实现方案。视觉上沿用现有管理端的工业级后台基线：固定侧栏与顶栏、右侧业务内容独立滚动。

## 1. 产品定位与目标

平台面向非标制造企业，将客户需求、技术版本、打样确认、生产协同、变更影响和交付风险放入同一可追溯闭环，避免错版投产、样品漏确认、变更未同步和交期失控。

核心闭环如下：

```text
客户/项目建档 → 需求评审 → 技术包发布 → 打样与客户确认
        → 生产协同 → 变更处理 → 交付归档 → 数据复盘
```

前端设计目标：

- 让不同岗位在一个页面内明确“当前对象、当前状态、下一步动作和阻断原因”。
- 让技术版本、样品确认、变更影响和风险规则可追溯、可解释、可下钻。
- 在高信息密度的 PC 场景下保持稳定、克制、可扫描的操作体验。
- 依据权限、数据范围和业务状态动态呈现页面、字段和动作，避免无效操作。

## 2. 目标用户

| 用户群 | 核心诉求 | 典型操作 |
| --- | --- | --- |
| 销售/项目经理 | 管住项目进度、客户确认和交期 | 建项目、维护需求、催办、发起变更、跟踪风险 |
| 技术/工艺人员 | 保证技术资料版本正确、可生产 | 上传发布图纸、维护 BOM/工艺/检验要求、分析变更 |
| 采购/计划/生产/质量人员 | 接收明确任务并及时反馈异常 | 更新任务、查看有效版本、报异常、检验与交付确认 |
| 管理层 | 快速识别延期、风险和资源负载 | 查看看板、下钻统计、关注高风险项目 |
| 系统管理员 | 管理权限、规则和系统运行 | 用户角色、流程参数、日志、归档、定时任务 |
| 客户确认人 | 安全地完成样品确认 | 通过短期链接查看脱敏资料、确认或驳回 |

### 2.1 权限呈现原则

- 权限由功能权限、数据范围、字段可见性和业务状态共同决定。
- 对无权限操作不展示入口；对状态不满足的操作保留禁用态与原因说明。
- 客户公共确认页只显示本次确认必需的脱敏信息，不展示内部成本、责任人和其他项目资料。

## 3. 核心使用场景

1. 项目经理新建非标订单，录入结构化需求、目标交期、成员和附件，发起需求评审。
2. 技术人员上传图纸、BOM、工艺和检验要求，完成版本校验与发布；现场人员始终查看当前有效版本。
3. 样品任务自动分解，质量检验后提交客户确认；未确认时系统在投产前阻断或触发预警。
4. 客户、技术或生产端提出变更，系统生成影响矩阵，责任人逐项反馈，全部验证后才能关闭。
5. 采购、生产、质量人员按任务处理并上报异常；风险中心聚合规则原因、责任人和处置计划。
6. 管理层按客户、项目经理、产品类型和时间查看交期、变更、延期、返工与负载，并可下钻原始业务对象。

## 5. 页面模块结构

### 5.1 工作台

- 顶部指标区：我的待办、临期任务、未读消息、关注项目；管理角色额外查看进行中项目、延期项目、待客户确认、待发布图纸、未完成变更与返工。
- 核心工作区：项目概览表，展示阶段、目标交期、剩余天数、负责人、样品状态、变更数和风险等级。
- 右侧信息区：风险卡片、待办列表、消息摘要和快捷操作。
- 快捷入口：按角色显示新建项目、上传图纸、提交客户确认、发起变更等。

### 5.2 项目中心

- 项目列表：关键字、状态、负责人、部门、日期、风险等级、是否超期等组合筛选；支持个人视图、列设置、导出和批量操作。
- 新建项目：客户、产品、数量、目标交期、优先级、负责人、项目成员、附件及结构化需求录入。
- 项目详情：
  - 顶部摘要：项目编号、名称、当前状态、客户、目标交期、负责人、风险等级和主操作。
  - 主内容：需求清单、阶段里程碑、业务时间轴、关联文件、样品、变更、任务和风险。
  - 侧栏：风险摘要、关键待办、成员与职责、客户确认入口或二维码。

### 5.3 技术资料

- 文件目录：按图纸、3D 模型、BOM、工艺卡、检验规范、客户附件分类浏览。
- 版本列表：文件名称、版本号、生效状态、发布人、生效日期、引用任务和下载记录。
- 版本详情：版本说明、附件、适用部件/物料、关联对象、历史版本与失效原因。
- 技术包维护：BOM、工艺路线、检验要求按页签维护，并显示与图纸版本的绑定关系。
- 发布审批：完整性校验结果、缺失项、例外审批入口、审核记录和发布回执。
- 版本对比：前后版本并列显示基础信息、变更说明、关联对象和人工上传的对比图。

### 5.4 样品管理

- 样品列表：项目、批次、引用版本、计划完成时间、检验结论、客户确认状态和临期标记。
- 样品详情：样品概况、任务进度、检验记录、问题整改、客户确认、轮次关联与历史对比。
- 客户确认：确认资料预览、截止时间、链接/二维码、确认结论、客户意见、凭证和销售代录标识。
- 特殊放行：仅在流程允许时显示，必须记录申请人、批准人、放行范围、有效期和风险承担说明。

### 5.5 变更中心

- 变更列表：变更编号、项目、类型、紧急程度、当前状态、发起人、影响程度、预计延期和审批进度。
- 变更详情：变更前后内容、原因、附件、审批流、业务时间轴与结果归因。
- 影响分析：按技术、采购、生产、质量等部门分组的影响矩阵，展示是否受影响、建议动作、责任人、反馈状态和预计延期。
- 执行与关闭：逐项反馈已重排、已改单、已退料、已返工、无需处理等结果；全部影响项处理并验证后才允许关闭。

### 5.6 任务中心

- 任务总览：采购、生产、检验、交付和超时任务按类型筛选，可切换列表与看板。
- 任务详情：当前有效技术版本、计划与实际时间、负责人、附件、处理记录和关联变更提醒。
- 执行反馈：接收、开始、暂停、完成、转派、催办和异常上报。
- 交付检查：任务完成、检验通过、资料齐套和严重风险关闭情况；不满足条件时给出阻断原因和处理入口。

### 5.7 风险、消息与统计

- 风险看板：低/中/高/严重四级分布、项目风险卡、风险趋势与责任人筛选。
- 风险详情：风险分值、原始指标、加减分明细、规则版本、计算时间、建议动作、处置计划和升级记录。
- 消息中心：未读/已读、业务类型、接收时间、催办记录；点击消息直接跳转对应对象与处理节点。
- 统计分析：交期、变更、延期归因、返工、样品效率、部门负载等图表，并支持下钻到项目、变更、任务或返工明细。

### 5.8 系统管理与工具

- 组织与权限：企业、部门、岗位、用户、角色、项目成员和责任配置。
- 配置：流程、规则参数、风险权重、催办周期、编号规则、字典与消息模板。
- 审计：登录、查询、导出、上传、发布、审批、作废和关键修改日志；归档恢复须展示授权与原因。
- 系统工具：Quartz 任务状态、执行日志、手动执行确认；代码生成配置、预览及 ZIP 下载。

## 6. 关键交互要求

- 状态只能通过明确业务动作推进，例如“提交评审”“发布版本”“批准变更”“确认交付”；不可提供泛化的“修改状态”。
- 关键操作放置在详情页顶部固定动作区，按主操作、次操作和高风险操作分层；无权限或状态不满足时说明原因。
- 阻断弹窗必须包含规则编号、当前问题、当前值、正确值或缺失项、影响范围、建议处理入口、确认与取消。
- 发布、作废、特殊放行、交期修改、归档恢复、批量导出等高风险操作需要二次确认、填写原因，并展示审计回执。
- 技术版本对比采用左右并列或上下对照，突出版本号、变更说明、关联对象与失效影响；文件预览不等同于版本有效。
- 系统识别的变更影响项如被删除，必须填写原因；批量操作必须逐条校验并反馈成功/失败明细。
- 大批量导入、导出采用异步任务，完成后经消息中心提供下载；导入应提供预校验结果和错误文件下载。
- 从列表进入详情、关闭抽屉或处理任务后，保留原筛选条件、分页与滚动位置。

## 7. 空状态、加载状态与异常状态

| 状态 | 设计要求 |
| --- | --- |
| 首次无数据 | 说明当前模块价值与下一步动作，例如“暂无项目，创建首个项目”；只在确有创建权限时显示主按钮 |
| 筛选无结果 | 明确显示已生效的筛选条件，提供“清除筛选”，不误导用户新建数据 |
| 无权限 | 展示权限范围说明和可联系对象，不泄露敏感数据或业务编号 |
| 业务未准备完成 | 如技术包不完整、样品未确认，显示缺失项、影响与可处理入口，不能伪装成普通空列表 |
| 页面加载中 | 首屏使用与真实布局一致的骨架屏；表格保留列结构；图表保留占位坐标，不整页白屏 |
| 局部提交中 | 仅锁定当前按钮或行操作，显示进度和可重试信息，不阻塞其他内容阅读 |
| 上传/导入中 | 显示文件名、进度、成功/失败数量、错误原因与错误文件下载入口 |
| 请求失败 | 保留已加载内容，局部展示重试按钮和可理解原因；网络错误、权限变化和规则阻断需区分呈现 |
| 无消息/无风险 | 使用克制的正向状态，例如“当前没有待处理风险”，同时保留筛选与刷新入口 |

## 8. 视觉风格规范

### 8.1 风格关键词

工业级 B 端、冷静克制、精准可靠、可追溯、高信息密度、轻边框、低圆角、浅灰工作画布、品牌蓝主操作、状态色只用于风险表达。

### 8.2 视觉原则

- 主色：深蓝用于主操作、当前状态和导航焦点；红、橙、绿仅表示严重风险、警告和完成。
- 字体：中文优先使用 HarmonyOS Sans SC、苹方或微软雅黑；编号、日期、版本与分值使用等宽数字以便扫描。
- 容器：白色面板配细边框，圆角控制在 4–6px；避免大面积渐变、重阴影和装饰性插画。
- 图表：优先展示趋势、分布和可下钻的数据，不使用无法解释的装饰性“健康度”图。
- 状态：状态标签、风险等级和版本有效性必须包含文字，不只依赖颜色。
- 密度：列表与数据页保持紧凑可读；详情页通过清晰分组和合理留白降低理解成本。

## 9. PC 端适配要求

- 推荐设计基准为 1440px 宽桌面；1280px 仍应完整可用；1024px 时侧栏收起为图标导航。
- 侧栏与顶栏固定，只有右侧内容区域纵向滚动；详情页标题、筛选栏和关键动作在长页面中可吸顶。
- 采用 12 列内容栅格：详情主内容与右侧风险/时间轴信息建议约为 2:1；宽屏最多三列指标卡，中屏降为两列。
- 表格保留编号、状态、负责人、目标日期和操作等关键列；非关键列允许隐藏或横向滚动，禁止把复杂业务表强行压成卡片。
- 支持浏览器缩放至 125%；按钮、表单与表格行保持可点击，不产生重叠和截断。
- 鼠标、键盘和触控板均可完成高频操作：Enter 搜索、Esc 关闭抽屉或弹窗、Tab 焦点顺序清晰；不依赖悬停才能获得关键信息。

## 10. 验收关注点

- 用户能按角色完成项目建档、技术发布、样品确认、变更协同、任务反馈、风险处置与统计下钻等高频流程。
- 关键状态、版本有效性、风险原因与阻断规则在页面中可见且可理解。
- 详情页、列表页、抽屉和弹窗的空、加载、失败、无权限和状态阻断表现一致。
- PC 端在 1440px、1280px、1024px 宽度下均不出现关键内容截断、操作重叠或无法滚动的问题。
- 页面展示与操作严格遵循权限、数据范围和业务状态控制。
