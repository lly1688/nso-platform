# V1.0 升级、试点与验收操作手册

本手册面向“按存量升级”的试点环境。业务事实以 MySQL 为准，Redis 只承载会话、限流和短期协同锁；不得把图纸、客户确认凭证或审计事实作为 Redis 的唯一副本。

## 1. 上线前准备

1. 在受控密钥系统或部署平台注入 `.env.example` 所列变量；生产必须设置 `SPRING_PROFILES_ACTIVE=prod`、强随机 `NSO_JWT_SECRET`、数据库/MinIO/Redis 真实凭据。
2. 生产环境固定 Redis 镜像为 `redis:8.6.1-alpine`（可通过 `NSO_REDIS_IMAGE` 注入，但只能使用完整的不可变版本标签）；严禁 `latest` 或主版本浮动标签。
4. 备份现网数据库和 MinIO 桶：保留一次可恢复的 MySQL 全量备份及对象存储清单/增量。将备份恢复到隔离实例并核对项目、技术版本、样品确认和附件哈希后，再进入维护窗口。

## 2. 存量升级

1. 使用包含 V1--V16 的同一制品启动应用。不要修改、重排、删除或手工标记已发布的迁移；Flyway 只会执行尚未成功记录的新增版本。
2. V7 创建默认企业租户 `DEFAULT`（ID=1），并为存量用户、文件、时间轴、变更影响和审计记录回填租户字段；V8 为变更影响项增加乐观锁版本；V9 补齐组织、角色、菜单和系统管理结构；V10 补齐角色权限、会话版本、职责分离和特殊放行治理；V11 初始化隔离环境演示业务数据；V12 补齐项目文件归属及现场角色权限；V13 追加项目经理关闭变更权限；V14、V15 增加工作台与汇总索引；V16 增加个人资料字段和演示职责部门。不可追溯操作者保留为系统迁移事实，不能伪造为业务人员。
3. 启动后检查 `flyway_schema_history` 中 V16 为成功状态，并抽检 `nso_tenant`、`nso_idempotency_key`、`nso_business_event`、`nso_attachment_relation`、`nso_special_release`、`nso_file_object.project_id`、`sys_user.avatar_file_id`、`sys_dept`、`sys_menu` 和 `sys_role_menu`。
4. 部署前先核对共享环境的 Flyway 历史：若 V12--V16 已被任何共享环境应用，禁止改写它们，后续修复只能追加 V17+；若尚未应用，可在首次发布前从空库重新验证。
5. 若迁移失败，停止应用、保留 Flyway 错误和数据库快照；在隔离恢复库修正环境或新增后续迁移，禁止修改已发布迁移的 checksum。

## 3. 试点验收用例

| 用例 | 操作 | 预期证据 |
| --- | --- | --- |
| AC-01 版本阻断 | 以旧图纸版本启动采购或生产任务 | `VERSION_MISMATCH`、当前版本提示、业务事件和审计记录 |
| AC-02 样品阻断 | 样品未客户确认时启动生产 | `SAMPLE_NOT_CONFIRMED` 与时间轴记录 |
| AC-03 变更影响 | 发起图纸变更并执行影响分析 | 图纸、BOM、采购、生产、样品、检验六类影响项 |
| AC-04 审批关闭 | 完成审批、逐项反馈、延期/返工汇总后关闭 | 审批节点、通知/待办、影响反馈和关闭事件 |
| AC-05 风险 | 上报异常并查看风险详情 | 分值、理由、规则版本、处置建议和升级记录 |
| AC-06 统计 | 从工作台指标进入项目/任务/风险明细 | 指标与同租户明细一致 |
| AC-07 越权 | 不同租户或非项目成员读取同一项目/附件 | 拒绝访问；不返回目标租户数据 |
| AC-08 幂等与并发 | 重放同一 `X-Request-Id`，并以旧 version 提交 | 幂等拒绝/重放提示、乐观锁冲突、审计追踪号 |

后端集成测试已覆盖 AC-01 至 AC-08：每个场景必须在干净 MySQL、Redis 容器中重新执行，校验接口响应、状态变化、业务事件和审计记录。试点人工执行的证据归档格式见 `V1.0_试点数据初始化清单与验收记录.md`。

安全回归还必须验证：无效、撤销和重放 Refresh Token 均返回 401；连续错误登录会返回 423；认证和下载接口限流返回 429 并携带 `Retry-After`；上传文件的扩展名与 MIME 不匹配会被拒绝；Quartz 手动执行仅接受白名单任务；代码生成器仅允许授权业务表并下载有效 ZIP。

## 4. 备份恢复演练

1. 每日备份 MySQL，并按日对 MinIO 做增量或版本保护；Redis 启用 AOF，恢复后失效会话应要求重新登录。
2. 每季度在隔离环境恢复最新数据库与对象存储备份，执行一次 Flyway V1--V16 校验和 AC-01/03/07 抽检。
3. 记录备份时间、数据范围、恢复耗时、RPO/RTO、问题和处置；建议目标为 RPO 不超过 24 小时、RTO 不超过 4 小时。

## 5. 阶段 5 验证与交付检查

- 在停止占用 `nso-admin` JAR 的本地实例后执行 `mvn clean test`。Testcontainers 必须使用 MySQL 8.0，完成 V1--V16 迁移，并验证默认租户、治理字段、个人资料边界、幂等约束、跨租户隔离、AC-01 至 AC-08 和安全边界。
- 执行 `npm run build`（`nso-web`）；登录页之外的业务页面必须按路由懒加载。以管理员、项目经理、技术、生产、质量和现场人员完成菜单、按钮和数据权限人工检查。
- 在受控验证环境中使用不含生产凭据的变量执行 Compose 结构校验、应用健康检查和 Quartz 审计。不得将本机 `.env` 的展开结果写入日志、报告或验收证据。
- 在预发布数据集上测量项目列表/详情 P95 不超过 2 秒、千级影响分析不超过 5 秒；未达标时优先优化索引、分页、查询范围或异步边界。
